# OpenCode invocation prompt — Cosmic Aces Developer

Use this message as the prompt for the scheduled/non-interactive OpenCode Developer run. The agent is `developer` (`mode: primary`) and its pinned model is `opencode-go/deepseek-v4-flash` (DeepSeek V4 Flash via OpenCode Go). Keep the CLI's `--agent developer` and `--model opencode-go/deepseek-v4-flash` flags in sync with `.opencode/agents/developer.md`.

```text
Use the `cosmic-aces-developer` skill from `.agents/skills/cosmic-aces-developer/SKILL.md`. Work in the Cosmic Aces repository and use the authenticated `linear` MCP connection for workspace `cosmic-aces` and team `Cosmic-aces` as the source of truth. Never use `LastMoveChess`. No project is currently configured; preserve the issue's project field as-is.

Absolute prohibition: AI agents must never, under any circumstances, make or authorize purchases; submit payment details; buy or increase tokens, credits, quotas, budgets, or usage limits; change/upgrade/downgrade/subscribe to/renew plans; or create accounts, trials, subscriptions, or workspaces. Stop and hand such actions to the human PO. Do not use workarounds.

Filesystem boundary: keep every generated build file, classpath, log, screenshot, and temporary artifact inside this repository, preferably in Maven's ignored `target/` directory. Never write to `/tmp`, `/private/tmp`, a home directory, or another external directory, and never request `external_directory` permission. Use repository-local paths such as `target/cosmic_cp.txt` and `target/cosmic_smoke.log` when needed. If validation is blocked, report it accurately; do not claim it passed or retry outside the repository.

Before claiming a child or finalizing a root, inspect the team's live Linear statuses. Child issues do not need an `In Review` state: after compile, applicable tests, a bounded app startup smoke check, and a successful GitHub push of the commit to the shared root branch, mark the child `Done` and record the evidence. If the repository has no applicable tests, say so. Do not attempt visual inspection; explicitly leave visual QA to the human PO. A semantic `In Review` state is required only to hand the root issue and final PR to Codex. Do not change Linear's team configuration.

Implement at most one eligible, unblocked child issue under an active root per invocation. Read the parent, siblings, dependency links, repository instructions, shared Linear workflow, Tech Lead analysis, and the child’s detailed implementation proposal first. Inspect the actual checkout and treat the proposal as the default route. You may correct a technical plan that is stale, incompatible with the codebase, or needlessly risky while preserving every PO acceptance criterion. Before coding, comment on the child with the adjustment, repository evidence, and acceptance mapping. If it would change player-visible behavior, scope, or PO criteria, stop and ask the Tech Lead/PO. Preserve existing user changes. Create or reuse the single task branch for the root issue, implement, run `mvn compile`, all applicable tests, and a bounded app startup smoke check with no startup exception. The smoke check must capture the PID of the exact app instance started in this invocation, terminate it with `kill "$APP_PID"`, and confirm termination with `wait`, including on errors or interruption. Never use `pkill`/`killall` or terminate pre-existing processes. State explicitly when there are no applicable tests. Do not attempt visual inspection; leave visual QA to the human PO. Make one focused commit and push it to the shared GitHub root branch; confirm the remote SHA before marking the child `Done`. Comment on Linear with the SHA, branch URL, exact verification results, and visual-QA limitation. Mark the child `Done` only if compile/tests/startup/push all pass. If any required check or push fails, keep it `In Progress` and report why. Codex does not verify children between implementation tasks. Do not open a PR until all children are Done.

When all children are Done, confirm all commits are on the remote branch, perform final validation, open one PR against the repository's actual default branch, link it in the root issue, and move the root to In Review. Do not merge the PR or close the root issue. If no work is eligible, make no changes. If there is a blocker, preserve the work and report it precisely.
```

`opencode run` supports non-interactive prompt execution. The repository runner is [`scripts/opencode-developer-cron.sh`](../../scripts/opencode-developer-cron.sh); install it in the user's crontab every 30 minutes. It uses a non-blocking OS lock, passes this fenced prompt to OpenCode, selects the `developer` agent and pins DeepSeek V4 Flash. The runner writes daily logs under `~/Library/Logs/CosmicAces/`. Cron may skip executions while macOS is asleep; keep the Mac awake for scheduled runs.
